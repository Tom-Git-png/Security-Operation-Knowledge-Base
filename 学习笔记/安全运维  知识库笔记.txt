安全运营防火墙：

1. 访问控制：哪些流量允许过，哪些拒绝。内网→外网、外网→内网、内网不同区域互访。
2. 威胁防护：病毒、漏洞攻击、Web 攻击、入侵防御 IPS，部分带 AV 杀毒、URL 过滤。
3. NAT 地址转换：内网私网地址上网；外网端口映射把服务器对外发布。
4. 日志审计：记录被拦截、放行的流量，安全运营最重要！排查告警、溯源、事件分析全靠防火墙日志。

-面试高频：防火墙和交换机路由器区别？
交换机：二层，只管转发，不判断安全；路由器：三层，路由选路；防火墙：基于安全策略做访问控制，能识别应用、用户、威胁，做安全检测。

基础核心概念：

1. 区域（安全域）。

企业标准划分：

- Trust：信任区域，企业内网办公电脑。
- Untrust：非信任，互联网外网。
- DMZ：隔离区，放对外服务器（网站、OA 服务器）。

-规则默认：不同安全域之间默认全部阻断流量，必须手动配置策略放通，同域内部默认互通。

-流量方向举例：

1）. Trust → Untrust：员工上网，内网访问互联网。
2）. Untrust → DMZ：外网用户访问网站服务器。
3）. Trust → DMZ：内网管理员管理 DMZ 服务器。
4）. Untrust → Trust：默认禁止！外网不能直接访问内网电脑，这是防火墙最基础防护。

2.防火墙策略（安全策略）。

策略五要素：源地址、目的地址、源端口、目的端口、服务 / 应用，动作（允许 / 拒绝）。

策略匹配规则：

1）. 从上往下匹配，匹配到第一条就执行，不再往下看。
2）. 策略顺序非常关键！精准策略放上面，宽泛策略放下面。
3）. 最后一条默认隐式拒绝：所有没有匹配上策略的流量全部丢弃。

工作踩坑点（面试常考）。
错误：把宽泛允许策略放最上面，后面精细策略永远不会生效。
案例：写了拒绝某个 IP 访问服务器，但是上面一条 any 允许所有，拒绝策略永远不生效。

3.NAT 两种模式，安全运营必须分清。

1）. 源 NAT（SNAT）：内网机器访问互联网，把内网私网 IP 转换成防火墙公网 IP。员工上网用这个。
源地址变，目的地址不变。
2）. 目的 NAT（DNAT，端口映射）：外网访问防火墙公网 IP 端口，转发到内网 DMZ 服务器，对外发布业务。
目的地址改变，源地址不变。

-易错点：配置 DNAT 之后，光做映射不够！还需要配套安全策略放通外网到 DMZ 的访问权限，很多新手只做映射不通业务，就是漏了安全策略。

4. 应用识别。

现代下一代防火墙 NGFW，不只是看端口。比如微信可以走 80、443 端口，防火墙可以识别 “微信” 这个应用，直接禁止微信，而不是封禁 80/443（封掉整个网页）。这是下一代防火墙和传统老防火墙最大区别。

场景 1：新增一条策略，允许办公网访问某台业务服务器。

操作流程（工作标准流程）。

1. 收集需求：源地址（办公网段）、目的地址（业务服务器 IP）、需要开放端口、申请人、用途、过期时间。
2. 在防火墙新建安全策略：源：办公网段，目的：业务服务器，服务：对应端口，动作允许。
3. 策略位置：放到合适位置，不要覆盖已有策略。
4. 测试验证：找一台办公电脑测试访问，确认通；确认其他无关流量不受影响。
5. 文档记录：变更台账记录：什么时候、谁申请、策略内容、到期时间。
6. 到期回收：临时策略到期必须删除，安全运营大忌：大量僵尸策略堆积。

-面试题：企业防火墙大量无用僵尸策略会带来什么风险？
答：策略变多，容易出现意外放行，产生安全漏洞；策略查找效率下降；日志混乱，故障排查困难。安全运营需要定期梳理清理冗余策略。

场景 2：排查业务不通，防火墙排错步骤（面试超级高频）。

用户反馈：业务访问不通，怀疑防火墙拦截，运营标准排查思路：

1. 看日志！防火墙会话日志 / 策略匹配日志，看流量是被哪条策略拒绝。
2. 检查源、目的、服务端口是否正确；策略顺序是否被上面策略覆盖。
3. 如果是对外业务：检查 DNAT 映射是否配置；有没有配套放通安全策略。
4. 查看会话表：看流量有没有建立会话。防火墙会话表看到流量，说明流量到达防火墙；没有会话，流量根本没过来，查上游网络。
5. 是否开启 IPS、应用过滤、URL 过滤，威胁特征拦截业务。
6. 测试完成，记录故障原因。

核心口诀：排错先看日志，再看会话表，最后看策略顺序。

场景 3：防火墙安全巡检（安全运营日常巡检项）。

1. 策略巡检：检查有没有宽泛策略 any-any 允许（源 any 目的 any 全部允许是高危）；清理过期临时策略。
2. 日志巡检：大量外网暴力破解、扫描攻击，IPS 告警，统计高危告警。
3. 设备状态：CPU、内存、磁盘；版本是否存在已知漏洞；许可是否过期（IPS、病毒库许可过期防护失效）。
4. NAT 配置巡检：检查有没有多余端口映射，防止把内网机器直接暴露公网。
5. 备份配置：定期备份防火墙配置文件，变更前一定要备份！

场景 4：应急事件：发现外网 IP 暴力扫描我们服务器。

安全运营处理步骤：

1. 防火墙查看日志，确认攻击源 IP，确认攻击行为。
2. 在防火墙配置黑名单，写拒绝策略拦截该源 IP。
3. 持续观察日志，确认攻击流量是否下降。
4. 记录安全事件，复盘：为什么这个 IP 能够访问到我们资产。

5.学习顺序。

1. 吃透安全域、安全策略五要素、匹配机制、SNAT/DNAT。
2. 理解会话表、日志的作用（运营最看重）。
3. IPS、URL 过滤、黑名单基础。
4. 熟悉变更流程、巡检、故障排查思路。
5. 找模拟器做实操。




Wireshark 基础抓包：

1、基础操作。

1）. 选择网卡：选你当前上网的网卡开始抓包。
2）. 过滤语法：
抓包数据量巨大，必须写过滤表达式，分捕获过滤、显示过滤，运营常用显示过滤。
常用显示过滤：

ip.addr == 192.168.1.10  # 只看源或者目的是这个IP。
ip.src == 192.168.1.10  # 源IP。
ip.dst == 113.10.20.30  # 目的IP。
tcp.port == 80  # tcp80端口。
udp.port == 53  # DNS 53端口。
http  # http流量。
dns  # dns流量。
tcp.flags.syn == 1  # SYN包，扫描行为。
!ip.addr == 192.168.1.1  # 排除某个IP。

2. 颜色规则。
- 黑色：校验错误、异常报文。
- 蓝色：TCP 通信正常。
- 黄色：UDP（DNS 等）。

3. 三次握手简单识别`SYN → SYN‑ACK → ACK`。
看到大量只有 SYN，没有 SYN‑ACK：大概率端口扫描。

4. 常用功能。
- 文件 → 打开：读取别人给的 pcap 流量包（工作中经常分析别人导出的流量）。
- 文件 → 保存：保存抓包文件 pcap。
- 右键数据包 → 追踪流 → TCP 流：看完整应用层会话，看 HTTP 请求内容，有没有 SQL 注入、XSS 攻击 payload。

-安全运营日常用 Wireshark 的场景。

1. 排查：防火墙做了 DNAT 映射，访问不通，看数据包 有没有到达防火墙、有没有回包。
2. 识别端口扫描：大量 SYN 包，多个目的端口。
3. 看 Web 请求：追踪 TCP 流，检查请求参数有没有攻击语句。
4. 看恶意外联：主机对外访问陌生恶意 IP。
5. DNS 异常查询：可疑域名请求。




HTTP/HTTPS 协议：

1. 网络协议（你刚学的 HTTP/HTTPS）。

1）. HTTP/HTTPS。

- HTTP：80 端口，明文；HTTPS：443，HTTP+TLS；TLS 握手流程；混合内容、HSTS；状态码 2xx/3xx/4xx/5xx。

常见状态码。

- 2xx 成功：200 OK；201 Created。
- 3xx 重定向：301 永久重定向；302 临时重定向；304 缓存未修改。
- 4xx 客户端错误：400 参数错误；401 未认证；403 禁止访问；404 找不到页面。
- 5xx 服务端错误：500 服务器内部错误；503 服务不可用。

- 请求方法 GET/POST/PUT/DELETE；Cookie、Session 区别。

2）. 常用端口（必须背熟，告警经常看端口）。

表格。

| 协议 | 端口 | 风险点 |
| --- | --- | --- |
| FTP | 21 | 明文传输，暴力破解 |
| SSH | 22 | 暴力破解重点 |
| Telnet | 23 | **明文，高危，禁止使用** |
| SMTP | 25 | 邮件发送，垃圾邮件、邮件钓鱼 |
| DNS | 53 | DNS 劫持、放大攻击 |
| HTTP | 80 | Web 攻击 |
| HTTPS | 443 | Web 攻击 |
| Mysql | 3306 | 数据库爆破，禁止对公网开放 |
| RDP | 3389 | Windows 远程，高频暴力破解 |
| Redis | 6379 | 未授权访问高危漏洞 |
| MongoDB | 27017 | 未授权访问 |

3）. TCP/IP。

- TCP 三次握手、四次挥手；UDP 无连接。
- SYN 洪水攻击原理；ICMP（ping）。
- NAT、代理、正向代理 / 反向代理。

2、Web 安全（运营高频告警，必背漏洞原理）。
 
SOC 运营不用深度挖漏洞，但**要看得懂告警，知道漏洞影响、利用方式、处置手段。

1）. SQL 注入：输入恶意 SQL 语句，读取数据库；危害：脱库；处置：过滤输入、WAF 拦截。
2）. XSS 跨站脚本：存储型、反射型、DOM 型；窃取 Cookie。
3）. CSRF 跨站请求伪造：借用户身份执行操作。
4）. 文件上传漏洞：上传木马 getshell。
5）. 文件包含漏洞：读取服务器敏感文件。
6）. SSRF 服务端请求伪造：攻击内网。
7）. 命令执行漏洞：执行系统命令，拿下服务器。
8）. 路径遍历（目录穿越 `../`）读取任意文件。

必背一句话。

- getshell：获取服务器命令执行权限。
- Webshell：网页木马，一句话木马。

3、安全运营 SOC 核心（重中之重，面试必考）。

1）. 告警分析流程（背熟，面试高频）。

-接收告警（WAF、IDS/IPS、EDR、防火墙、日志平台）。
-**告警分级**：高危、中危、低危、误报。
-核实：看日志、源 IP、访问载荷、行为。
-判断真实攻击还是误报。
-处置：阻断 IP、隔离主机、清除恶意文件。
-记录、复盘、输出报告。

2）. IDS / IPS / WAF / EDR 区别（必背）。

-IDS 入侵检测系统：只检测告警，不阻断；旁路部署。
-IPS 入侵防御系统：检测 + 阻断；串联部署。
-WAF Web 应用防火墙：专门防护 Web（SQL 注入、XSS 等）。
-EDR 终端检测与响应：主机层面，查杀病毒、木马、进程行为监控。

4. 日志（运营天天看）。

- 日志类型：防火墙日志、Web 访问日志、系统日志、EDR 日志、数据库日志。
- Windows 日志：安全日志、系统日志、应用日志；事件 ID（登录 4624，登录失败 4625）。
- Linux 日志：`/var/log/messages`、`/var/log/secure` ssh 登录日志。

重点：暴力破解看大量登录失败日志。

5. 应急响应（必背！！）。

应急响应 6 步法（标准，考试面试直接默写）。

1）. 准备：预案、工具、联系人。
2）. 检测：确认事件，收集证据，判断影响范围。
3）. 遏制：隔离主机、封禁 IP、切断攻击链路，防止扩大。
4）. 根除：清除恶意程序、木马、修复漏洞、修改弱口令。
5）. 恢复：业务逐步恢复，验证安全。
6）. 总结：复盘，写报告，优化防护。

常见安全事件：暴力破解、Web 入侵、勒索病毒、挖矿木马、钓鱼邮件。

勒索病毒行为：加密文件，修改后缀；挖矿：CPU 占用异常高。

6、漏洞与威胁基础

1. CVSS 漏洞评分：0‑10 分；高危 7‑10，中 4‑6.9，低 0‑3.9。
2. CVE 编号：公开漏洞编号 CVE‑2021‑xxxx。
3. 威胁情报：IOC 指标（IP、域名、MD5 哈希值）。
4. 常见攻击类型：

- 暴力破解：批量猜密码。
- 弱口令。
- 钓鱼攻击（邮件钓鱼）。
- 0day：厂商还没有补丁的漏洞。
- Nday：已经公开，有补丁的漏洞。

7、等保 2.0（网络安全等级保护，运营必考）。

1）. 等级划分：1、2、3、4 级；企业一般等保 2 级、等保 3 级。
2）. 五个层面：物理环境、网络、主机、应用、数据安全。
3）. 等保工作流程：定级→备案→建设整改→测评→定期复查。




常见端口及其风险：

- 0‑1023：知名端口，系统服务默认占用，root 权限才能监听。
- 1024‑49151：注册端口，业务程序、中间件常用。
- 49152‑65535：动态 / 私有端口，客户端临时使用，服务器一般不对外监听。

端口；协议 ；服务名称；作用；SOC记忆点；研判要点；

0-1024
-21；TCP；FTP；文件传输；暴力破解、匿名 FTP 登录、文件泄露、上传恶意文件；公网尽量不要开放；告警看到大量 21 端口登录失败 = 爆破。
-22；TCP；SSH；远程Linux服务器管理；SSH 暴力破解、弱口令爆破、密码喷洒、密钥泄露入侵；公网大量 22 端口登录失败，高危告警；禁止弱口令，建议密钥登录，限制源 IP。
-23；TCP；TELNET；明文远程登录；全部明文传输，账号密码裸跑，极易被抓包窃取，暴力破解；高危，业务允许的情况下禁止使用 Telnet，优先 SSH；公网看到 23 开放视为风险资产。
-25；TCP；SMTP；邮件发送服务；邮件中继滥用、垃圾邮件、SMTP 暴力破解；服务器对外 25，是否为合法邮件服务器；异常大量外发邮件告警。
-53；UDP/TCP；DNS；域名解析；UDP：DNS 放大反射 DDoS 攻击；DNS 劫持、区域传送漏洞；内网 DNS 正常；公网服务器不要开放 53 做递归 DNS，防止被利用做 DDOS 放大器。
-67/68；UDP；DHCP：地址分配；内网使用；DHCP 欺骗；一般不对外网开放；公网出现 67/68 监听属于异常。
-69；UDP；TFTP；简单文件传输；无认证，任意文件读取下载，木马回传文件；几乎不会公网开放，扫描发现 69 开放，高风险；几乎不会公网开放，扫描发现 69 开放，高风险。
-80；TCP；HTTP；网页服务，明文 web；Web 攻击：SQL 注入、XSS、文件上传、webshell；目录遍历；普通 web 业务正常；注意异常访问路径，大量恶意 payload 访问。
-110；TCP；POP3；接收邮件；明文传输，暴力破解；尽量改用加密端口 995。
-111；TCP/UDP；RPCbind；RPC 远程调用；NFS 依赖；RPC 漏洞，信息泄露，经常被扫描爆破；公网严禁开放 111，很多勒索病毒扫描此端口。
-135；TCP、MS-RPC；Windows RPC 服务；永恒之塔相关漏洞、勒索病毒扫描、横向移动；公网绝对禁止开放 135；内网域环境正常，外网看到 135 告警高危。
-137/138；UDP；NETBIOS；Windows 网上邻居；信息泄露，获取主机名，内网探测；勒索病毒扫描；禁止对公网开放。
-143；TCP；IMAP；邮件接收；明文，暴力破解，替换加密 993。
-161/162；UDP；SNMP；网络设备监控；弱团体字 public，设备信息泄露，读取修改设备配置；公网严禁开放；团体字不要使用默认 public/private。
-389；TCP/UDP；LDAP；轻量目录访问协议，域控；LDAP 查询，信息泄露，LDAP 注入，暴力破解；域控内网正常，不要暴露公网；公网开放 389 属于高危风险。
-443；TCP；HTTPS；加密网页 TLS；web 全套攻击；证书过期、证书漏洞；SSL/TLS 漏洞；正常 web 业务；注意恶意 https 请求。
-445；TCP；SMB文件共享（WIndows）；Windows 文件打印机共享；永恒之蓝 MS17‑010，勒索病毒最爱的端口，SMB 暴力破解；SOC 最高频告警端口之一。严禁公网开放 445！内网域正常，外网看到 445 直接判定高危资产。
-514：UDP；Syslog；日志接收；日志接收；日志注入；一般内网收集日志用，不对外；公网开放 514 异常。

HTTPS/TLS、证书、对称 & 非对称加密：

1. HTTP 和 HTTPS 的关系。

HTTP：明文传输。客户端和服务器之间所有数据裸奔，网络上抓包就能直接看到账号、密码、聊天内容。不安全。

HTTPS = HTTP + TLS。
HTTP 负责业务数据（网页内容），TLS 负责在传输层给 HTTP 的数据做加密保护。现在基本已经不用 SSL，全部使用 TLS，日常口语依旧叫 SSL 证书。

简单理解：TLS 就是架在 HTTP 和 TCP 中间的一层加密隧道，所有 HTTP 数据塞进这个加密隧道再发出去。

2. 对称加密。

- 特点：同一个密钥，用来加密，也用来解密。
举例子：一把钥匙，上锁用它，开锁也用它。
- 优点：速度快，性能高，适合加密大量业务数据。
- 缺点：密钥分发难题。
如果直接在网络传输密钥，密钥被窃听截获，全部加密数据直接泄露。
 
TLS 真正传网页内容的时候，数据本体就是用对称加密加密的。

3. 非对称加密。

- 一对密钥：公钥、私钥。
公钥：可以公开给所有人；
私钥：服务器自己严格保管，绝不外传。
- 规则：

1）. 公钥加密的数据，只能对应的私钥解密。
2）. 私钥签名的数据，可用公钥验证真伪。

- 优点：解决密钥交换信任问题，不怕公钥公开。
- 缺点：运算很慢，不适合加密大体积数据。

TLS 不会用非对称加密去加密网页，它只用来做两件事：身份校验、交换对称会话密钥。

4. 数字证书（SSL/TLS 证书）。

思考一个问题：如果只有非对称加密，怎么确认 “对方服务器不是假冒的？”。
假如有个中间人拦截，把假的公钥发给你，你拿假公钥加密，中间人拿自己私钥解密，中间人攻击就成功。

数字证书就是服务器的官方身份证。
证书由可信 CA 机构颁发，里面包含：

1. 网站域名。
2. 服务器的公钥。
3. CA 机构的数字签名。
4. 有效期、算法等信息。

证书的核心作用 3 点（SOC 考点）：

1. 证明这个公钥确实属于这个网站，不是黑客伪造的公钥。
2. 客户端（浏览器）用 CA 根证书验证证书签名，判断证书是否合法可信。
3. 证书过期、篡改、域名不匹配，浏览器直接报不安全告警。。

私钥依旧保存在服务器，证书（公钥信息）可以对外公开。

5. TLS 握手简化流程（HTTPS 建立连接）。

1. 客户端发起连接请求，告知自己支持的加密套件。
2. 服务器返回自己的数字证书（携带服务器公钥）。
3. 客户端校验证书：检查签名、有效期、域名，证书非法直接断开连接。
4. 证书校验通过，客户端生成一个随机的对称会话密钥，用服务器的公钥加密，发给服务器。
5. 服务器使用自己的私钥解密，拿到这个对称会话密钥。
6. 现在客户端、服务器两边都拥有相同的对称密钥。
7. 后续所有网页业务数据，全部使用对称加密传输，完成加密隧道。

6. SOC‑L1 视角，需要记住的风险点。

1. 证书过期、证书域名不匹配、证书签名无效 → 可能中间人攻击，业务告警需要关注。
2. 私钥泄露：黑客拿到服务器私钥，可以解密历史 TLS 流量，属于高危事件。
3. 中间人攻击：伪造证书，如果客户端信任恶意 CA，HTTPS 也会被破解。
4. 老旧 TLS 版本（TLS1.0/1.1）存在漏洞，SOC 日常会扫描检测是否启用弱版本。

总结记忆口诀。

对称加密干活传数据，速度快；
非对称加密交换密钥验身份，速度慢；
数字证书担保公钥真假，防止遇到假服务器。
HTTPS 就是 HTTP 套上 TLS 加密隧道。




NAT、公网、内网、代理、VPN、CDN：

1.内网（私网） & 公网。

内网（私网）。

公司电脑、家里手机电脑、服务器内网口，属于内网。
使用私网 IP 段（规定好的地址，互联网路由器不会路由这些地址）。
常见私网段：

- 10.0.0.0/8。
- 172.16‑31.0.0/12。
- 192.168.0.0/16。

特点：

1）. 不能直接访问互联网，内网 IP 全世界可以重复使用；每家公司都可以有 192.168.1.1，互不冲突。
2）. 内网设备外部互联网无法主动直接访问它。

公网。

公网 IP 是互联网上唯一的地址，全球不能重复。
家里光猫、公司出口防火墙、网站服务器会分配公网 IP，可以互联网互相访问。

SOC 考点：日志看到源 IP 是 192.168 开头，这是内网地址，不是互联网黑客源地址。真正公网攻击源，是公网 IP。
问题：内网一大群设备，只有 1 个或者少量公网 IP，怎么上网？—— 靠NAT。

2.NAT 网络地址转换。

通俗讲：地址翻译，相当于公司大门传达室。

公司几十台内网机器（192.168.x.x）共享一个公网 IP 上网。

- 内网机器访问外网，防火墙 / 路由器做 NAT：把源私网 IP + 端口替换成公网 IP + 端口，发往互联网。
- 外网响应回来，再根据端口映射，把流量转发回对应的内网主机。

两种常见 NAT（SOC 要分得清）。

1）. 源 NAT（SNAT）：内网访问外网。
内网主机出去上网，转换源地址。家里、公司员工上网就是 SNAT。
日志里外网看到的源 IP 全是出口公网 IP，看不到真实员工内网 IP。
2）. 目的 NAT（DNAT，端口映射）：外网访问内网服务。
把访问公网 IP: 端口的流量，转发到内网某台服务器。
例：公网访问 IP:8080 → 映射内网 192.168.1.10:80。对外暴露内网服务。

SOC‑L1 安全风险。

1）. DNAT 端口映射，如果配置不当，把高危内网服务暴露公网，容易被扫描爆破。告警看到新增 DNAT 策略需要关注。
2）. SNAT 之后，外网日志看不到真实内网主机，排查攻击时需要查 NAT 会话表追溯。
3）. 设备在 NAT 后面，公网无法主动连接。

一句话记 NAT：SNAT 出去上网；DNAT 把内网服务对外开放。

3.代理（Proxy）。

代理服务器：流量的中间人转发服务器。客户端不直接访问目标网站，请求发给代理，由代理代为访问目标，再把结果返回客户端。

分类：

1）. 正向代理（代表客户端）。
员工上网代理、翻墙代理。客户端指定代理服务器。网站看到的访问源是代理 IP，看不到真实用户 IP。
2）. 反向代理（代表服务器）。
架在网站服务器前面，用户访问代理，代理转发给后端多台业务服务器。Nginx 就是典型反向代理。用户不知道后端真实内网服务器地址。

和 NAT 简单区分（SOC 高频混淆点）。

- NAT：三层 IP 地址转换，工作在网络层，只改 IP 端口，看不懂 HTTP 内容。
- 代理：应用层转发，能解析 HTTP/HTTPS 协议，可以过滤 URL、篡改请求内容、做访问控制。

风险点：
正向代理 IP 经常被黑客利用做跳板攻击；告警里大量恶意行为来自代理 IP 属于常见现象。反向代理后端如果泄露，会造成内网暴露。
VPN 虚拟专用网络。

作用：在公网互联网上，搭一条加密隧道，把异地的内网连通起来。

两种常见场景：

1）. 远程接入 VPN（员工 VPN）：居家员工，互联网拨号连公司 VPN 网关。连通后员工电脑获得公司内网 IP，可以访问公司内网系统，流量全部加密跑在公网之上。
2）. 站点到站点 VPN：分公司和总部，公网建立加密隧道，两个内网互通。

关键点：

- VPN 隧道内传输的是**内网流量**，底层跑公网。
- 所有隧道内流量加密，公网抓包只能看到 VPN 网关公网 IP，看不到里面业务数据。

SOC‑L1 安全关注点。

1. VPN 账号被盗：黑客拿到 VPN 账号密码，就可以进入企业内网，横向移动，属于高危风险。
2. VPN 登录日志是 SOC 重点审计对象：异地登录、异常时间登录要告警。
3. VPN 连通之后，用户同时拥有互联网 + 内网访问权限，如果主机中毒，会直接威胁内网。
 
区分 VPN vs 代理：
VPN：拿到内网地址，整个系统所有流量走隧道；
代理：只转发指定应用流量，不会分配对方内网 IP。

4.CDN 内容分发网络。

通俗：遍布全国全世界的缓存代理节点集群。

网站把静态资源（图片、js、css、视频）放到 CDN 节点。用户访问网站，不会直达源站服务器，访问就近 CDN 节点。

- 用户：访问 CDN 节点 IP，获取缓存好的资源，速度快。
- CDN 节点没有资源时，才回源站拉取内容。

SOC 重点，非常重要。

1. 用户看到的 IP 是CDN 节点公网 IP，不是网站真实源站 IP。
2. 如果黑客 DDoS 攻击，攻击流量打在 CDN 节点，保护后端源站不被打垮。
3. 但是：一旦源站真实 IP 泄露，攻击者会绕过 CDN 直接打源站，DDoS、Web 攻击直接打业务服务器。这是 SOC 经常遇到的风险场景。
4. WAF 经常集成在 CDN 上，攻击请求在 CDN 节点就被拦截，不会到达源站。

日志分析坑：访问日志源 IP 全部是 CDN 节点 IP，不是真实用户 IP，需要读取 HTTP 头部字段拿真实客户端 IP；如果配置错误，会导致日志取证失效。




IP、子网掩码、网段划分：

一、IP 地址是什么。

IP（IPv4）：用来在网络里标识一台主机的地址，32 位二进制，习惯写成 4 段十进制，点分十进制。
格式：A.B.C.D，每一段范围 0~255。
例子：192.168.1.10、10.0.5.20。

- 每一段是 8 个 bit，所以最大值是 \(2^8-1=255\)。
- 一共 32bit，总共有 \(2^{32}\) 个 IPv4 地址。

SOC 重点记忆：内网私有 IP 段（不会在公网路由，外网不能直接访问）。

1. 10.0.0.0 ~ 10.255.255.255（大内网，企业总部常用）。
2. 172.16.0.0 ~ 172.31.255.255。
3. 192.168.0.0 ~ 192.168.255.255（家庭、小办公最常见）。

日志看到上面这三类，直接判断：内网 IP；除此之外大多是公网 IP。

二、子网掩码（核心，SOC 最常用）。

子网掩码：也是 32 位，同样写成 4 段十进制。
作用：区分 IP 里哪一部分是【网络位（网段）】，哪一部分是【主机位（设备）】。
规则：子网掩码二进制里，1代表网络位，0代表主机位。

常见掩码：

- 255.255.255.0→ 二进制：11111111.11111111.11111111.00000000，网络位 24 位，简写 /24。
- 255.255.0.0 → /16。
- 255.0.0.0 → /8。
 
简写格式（CIDR）：192.168.1.0/24，意思 IP 是 192.168.1.0，掩码 255.255.255.0。
SOC 日志、防火墙、EDR 里大量出现 CIDR，一定要看得懂。

方法：IP 和子网掩码做【按位与运算】，结果相同 = 同一网段；结果不同 = 不同网段。

举例子：
IP1：192.168.1.10，掩码255.255.255.0。
IP2：192.168.1.20，掩码255.255.255.0。

和掩码做按位与：
192.168.1.10 & 255.255.255.0 = 192.168.1.0。
192.168.1.20 & 255.255.255.0 = 192.168.1.0。
网段相同 → 两台机器可以二层直接通信，不需要路由器转发。

再换一个：IP3 192.168.2.10，掩码 / 24。
按位与结果：192.168.2.0，和上面网段不一样，属于不同网段。

SOC 应用场景：告警源 IP 192.168.1.5，目的 IP 192.168.1.100，掩码 / 24。
快速判断：同网段，这是内网横向流量，属于高危告警，要重点关注！

三、网段里面两个特殊地址（不能分配给主机）。

网段算出后，有两个地址保留，不能给电脑、服务器使用：

1. 网络地址：网段本身，主机位全部为 0。例如192.168.1.0/24。
2. 广播地址：主机位全部为 1。192.168.1.255/24，发给这个地址，同网段所有主机都收到。

/24 网段例子：
网段：192.168.1.0/24。
可用主机范围：192.168.1.1 ~ 192.168.1.254。
广播地址：192.168.1.255。
总主机数 2^8=256，减去 2 个保留地址 → 254 个可用 IP。

再看 /16 例子：172.16.0.0/16，掩码 255.255.0.0。

网络位 16 位，主机位 16 位。
主机数量：2^{16}=65536，减去 2 → 可用 65534 台主机。
网段：172.16.0.0，广播：172.16.255.255。

四、简单网段划分（企业为什么要划分子网？SOC 理解层面）。

场景：企业拿到一个大网段 192.168.1.0/24，一共 254 个 IP。
部门：办公区、服务器区、监控区。

如果全部放同一个网段：
省事。
问题：一台主机中毒，发广播，整个网段全部受影响；一旦横向渗透，所有机器都能访问。安全上非常差。

所以网络工程师会子网划分，把大网段切成多个小网段，用防火墙隔离。

示例划分：母网段 192.168.1.0/24，我们借 1 位主机位当网络位，分成 2 个子网。
借 1 位，掩码变成 /25（255.255.255.128）。
子网 1：192.168.1.0/25，可用 IP：1~126，广播 127。
子网 2：192.168.1.128/25，可用 IP：129~254，广播 255。

安全价值（SOC 重点）：
办公区放在192.168.1.0/25，服务器区放在192.168.1.128/25。
防火墙策略：禁止办公网段直接访问服务器网段。
就算办公电脑被木马拿下，横向也无法直接访问服务器，缩小攻击面。
 
子网划分核心一句话：借主机位，变成新的网络位，切出更小网段，隔离网络，提升安全。




Linux 网络安全运维常用命令：

1. useradd —— 创建系统用户（账号安全）。

useradd testuser  # 创建用户testuser，默认同时创建同名组/home/testuser。
useradd -m testuser  # -m 自动创建家目录（最常用）。
useradd -s /sbin/nologin testuser  # 创建不能登录的系统账号（服务账号）。

设置密码。

passwd testuser。

2. chmod —— 修改文件 / 目录权限（权限安全）。

作用：修改文件读写执行权限，控制谁能读、写、运行文件。
权限分为三类：所有者 u、所属组 g、其他用户 o；r=4 读，w=2 写，x=1 执行。

chmod 755 test.sh  # 所有者读写执行，组和其他人读+执行。
chmod 644 test.txt  # 文件常用：所有者读写，其他人只读。
chmod +x test.sh  # 给文件增加执行权限。
chmod -R 700 /data  # -R 递归修改目录下所有文件权限。

3. chown —— 修改文件所有者和所属组。

作用：改变文件属于哪个用户、哪个用户组。

chown nginx:nginx index.html  # 所有者nginx，组nginx。
chown root test.txt  # 仅修改所有者为root。
chown -R www:www /web  # -R递归修改整个目录。

4. sudo —— 普通用户临时获取管理员权限。

作用：普通用户不需要登录 root，临时执行 root 权限命令。
配置文件：`/etc/sudoers`（用`visudo`编辑，不要 vi 直接改）。

sudo ls /root  # 普通用户临时root权限查看root目录。
sudo su -  # 切换成root。

5. /var/log/secure —— 安全日志（登录审计，入侵排查重点！）。
 
RHEL/CentOS 系列；Ubuntu 是 `/var/log/auth.log`。
作用：记录ssh 登录、su 切换、sudo 操作、账号认证失败日志，排查暴力破解、异常登录。

# 查看所有登录失败记录。
grep Failed /var/log/secure。
# 查看登录成功记录。
grep Accepted /var/log/secure。

6. ps —— 查看系统进程（查杀可疑进程必备）。

作用：列出当前运行进程，排查木马、恶意进程、挖矿程序。

ps aux  # 最常用！a所有用户进程，u详细信息，x无终端进程（木马经常无终端）。
ps efH  # 树形展示进程父子关系，看恶意进程父进程。

7. netstat /ss —— 查看端口监听，找对外端口。

netstat 旧工具；ss 是新一代，速度更快，推荐优先 ss。
作用：查看网络连接、监听端口，排查后门程序、恶意端口外联。

netstat -antlp；
ss -antlp：
参数说明：a所有连接，n数字端口不解析域名，t tcp，l监听端口，p显示进程PID/程序名。

8. 查杀可疑进程（安全运维实操）。

流程：

1. `ps aux` 或者 `ss -antlp` 找到可疑进程 PID。
2. 先用 `ls -l /proc/PID/exe` 看进程对应程序路径（确认恶意文件）。
3. 杀死进程。

kill  1234  # 正常终止PID=1234进程。
kill -9 1234  # 强制杀死进程（杀不掉的时候用，慎用）。

9. tail —— 实时查看日志。

作用：查看日志末尾，最常用实时跟踪日志。

tail /var/log/secure  # 默认看最后10行。
tail -n 50 /var/log/secure  # 看最后50行。
tail -f /var/log/secure  # -f 实时滚动输出日志（实时监控登录行为）。
tail -F /var/log/secure  # 文件被轮换也能继续跟踪（生产推荐）。

10. grep —— 文本过滤，检索关键字。

grep "Accepted" /var/log/secure  # 筛选登录成功日志。
grep -i "failed" /var/log/secure  # -i忽略大小写。
grep -v "root" /var/log/secure  # -v反向匹配，排除root行。

如果服务器疑似被入侵，安全运维排查步骤：

1. 查看账号：`cat /etc/passwd`，检查可疑账号。
2. 查看登录日志：`tail -f /var/log/secure | grep -E "Failed|Accepted"`，看爆破、异常登录 IP。
3. 查看端口监听：`ss -antlp`，找出陌生监听端口和对应 PID。
4. 查看进程：`ps aux`，根据 PID 找到可疑恶意进程。
5. 查看进程程序路径：`ls -l /proc/$PID/exe`。
6. 查杀：`kill -9 PID`，删除恶意文件。
7. 复查：再次 ps、ss 确认进程端口消失，检查定时任务 / 开机自启。

MITRE ATT&CK：

一、MITRE ATT&CK 到底是什么。

MITRE 是美国非营利研究机构，ATT&CK 全称：Adversarial Tactics, Techniques & Common Knowledge
翻译：对手战术、技术与通用知识库。

一句话大白话：

ATT&CK 是一套攻击者完整攻击流程的标准化字典。把黑客从「踩点到最后清理痕迹」每一步会干什么，统一命名、分类。
以前：安全运维全凭经验，A 工程师叫 “内网横向移动”，B 工程师叫 “内网渗透”，叫法混乱。
有 ATT&CK 之后：全世界 SOC、SIEM（Splunk ES）、厂商统一语言。告警、检测规则、威胁报告全部用这套编号。

最重要的价值：

1. Splunk ES 的所有关联检测规则（Correlation Search），全部映射 ATT&CK 战术 (Tactic) 和技术 (Technique)。
2. 告警出来之后，你研判事件，要判断这个攻击属于 ATT&CK 哪个阶段，写事件报告用 ATT&CK 编号。
3. 威胁狩猎：在 Splunk 写 SPL 检索，就是基于 ATT&CK 技术去查找日志里对应的攻击行为。
4. 漏洞 / 威胁情报，厂商报告都会标注 ATT&CK 编号，快速看懂攻击链路。

- Tactic（战术，大阶段）：攻击者目标，动词短语，对应攻击的一个环节。编号 T00xx。
- Technique（技术，具体手段）：攻击者实现这个目标用的方法。编号 Txxxx。
子技术 Sub-technique：Txxxx.001，同一个技术下面细分方式。

举个例子：
战术：T1059 命令和解释器（Command and Scripting Interpreter）。
子技术：T1059.001 PowerShell，代表攻击者使用 PowerShell 执行恶意代码。

二、ATT&CK 矩阵（Enterprise 企业矩阵，SOC 运维重点）。

Enterprise ATT&CK：针对企业内网、服务器、AD 域、终端，就是你日常在 Splunk 里采集日志要防护的场景。
一共 14 个战术，按攻击时间先后顺序排列，从入侵前→入侵→内网横向→持久驻留→数据窃取→清理痕迹。

下面逐个战术讲解，重点标注【Splunk/SOC 运维关注点：对应什么日志、怎么检测】。

1. Reconnaissance 侦察（T1595~T1598）。

战术目标：黑客入侵前收集目标信息。
攻击者行为：子域名扫描、端口扫描、网页爬虫、LinkedIn 收集员工邮箱、查询公开漏洞。

Splunk 运维关注点：

- 日志来源：防火墙、WAF、DNS、流量日志。
- 检测场景：短时间大量端口扫描，大量 DNS 查询，对官网大量请求。
- Splunk SPL：统计单一源 IP 访问大量不同目的端口，触发告警。

注意：侦察阶段很多是外网行为，还没打进内网，告警多为预预警，很多是误报，需要研判。

2. Resource Development 资源开发（T1583~T1589）。

战术目标：黑客准备攻击工具，搭建 C2 服务器、注册恶意域名、购买木马、准备钓鱼文件。

一般企业内部日志看不到这个阶段，更多来自外部威胁情报。
SOC 用途：情报 IOC（恶意域名、IP）入库到 Splunk lookup 表，后续匹配日志告警。

3. Initial Access 初始访问（T1560~T1566）。

战术目标：拿到企业内网的第一个立足点，打进大门。
常用技术：钓鱼邮件、漏洞利用、外部暴露服务暴力破解（RDP/SSH/ 网站后台）。

Splunk 运维重点【高频告警来源】。

日志：邮件网关日志、Windows 登录日志 4625 失败登录、Web 访问日志、防火墙日志。

例子：
- T1566.001 钓鱼邮件（钓鱼附件）。
- T1190 通过公共应用漏洞入侵（如 Exchange、Log4j）。

Splunk ES 大量告警都出自【初始访问】，是 SOC 最常研判的一类告警。

4. Execution 执行（T1059 系列）。

战术目标：在受害者机器上运行恶意代码。
常用技术：powershell、cmd、wscript、rundll32、wmic、mshta 执行恶意程序。

Splunk 运维【重中之重！】。

日志：Sysmon（进程创建日志 EventCode 1）、Windows 安全日志 4688 进程创建

例子 T1059.001 PowerShell，Splunk 写 SPL 监控 powershell 异常参数（base64 编码命令），ES 自带这条检测规则。
只要恶意程序跑起来，一定会在这里留下进程日志。

5. Persistence 持久化（T1037、T1547 等）。

战术目标：就算机器重启，黑客依然保留权限，不会掉线。
技术：开机启动项、计划任务、服务、注册表、创建后门账号、WMI 事件订阅。

Splunk 检测日志：

Windows 事件日志：新建用户 4720，创建计划任务 4698，注册表修改、新增系统服务。

典型场景：黑客入侵主机后，新建后门账号，每次开机自动运行木马。
事件研判看到新建账号，直接判定高危事件。

6. Privilege Escalation 权限提升（T1068、T1548）。

战术目标：拿到更高权限。普通用户→管理员 / 域管理员。
手段：本地漏洞提权、利用服务漏洞、窃取凭证。

日志：进程权限变化、服务修改、特权登录事件。

黑客拿到普通账号不够，必须提权，才能控制更多机器。

7. Defense Evasion 防御规避（T1027、T1562）。

战术目标：躲避杀毒、EDR、SIEM（Splunk），隐藏自己，不让安全设备发现。
技术：日志删除、修改系统时间、混淆代码、禁用安全服务、删除事件日志。
SOC 重点：监控「清除 Windows 事件日志（EventCode 1102）」，一旦出现就是高危！

黑客干完坏事第一件事，经常是删日志。Splunk 一旦捕获 1102，是高优先级告警。

8. Credential Access 凭证访问（T1003，非常高频）。

战术目标：偷账号密码、NTLM 哈希、kerberos 票据。
手段：mimikatz 抓取内存密码、dump SAM 数据库、凭证缓存窃取。

日志：LSASS 进程访问（Sysmon）、SAM 文件读取，Kerberos 异常票据请求。

拿到凭证，就是为下一步横向移动做准备。这个是域环境最经典攻击环节。

9. Lateral Movement 横向移动（T1021）。

战术目标：从已经拿下的一台电脑，跳到内网其他主机，扩大控制范围。
技术：SMB、RDP、WMI、PsExec，Pass-the-Hash 哈希传递攻击。

Splunk 重点日志：
Windows 远程登录 4624，内网跨主机 SMB 连接、WMI 远程进程创建。

企业内网安全事故，最可怕的就是横向移动，一台沦陷，整个域被拿下。Splunk ES 专门有横向移动检测模型。

10. Collection 数据收集（T1005、T1114）。

战术目标：在受害主机搜集要偷的数据：文档、数据库、邮件。
行为：读取本地文件、截图、抓取邮箱。

日志：文件访问审计日志，进程读取大量文档。

11. Command and Control 命令与控制 C2（T1071）。

战术目标：木马和黑客服务器建立通信，接收指令。
手段：DNS 隧道、HTTP/HTTPS 隐蔽通信，ICMP 隧道。

日志：DNS 日志、外网出站流量、防火墙日志。

Splunk 场景：发现内网主机主动连接恶意 IP / 域名（威胁情报 IOC 匹配告警）。

12. Exfiltration 数据外渗（T1020）。

战术目标：把窃取到的企业数据传出内网。
行为：打包大量文件上传到外网网盘、邮件外发、分段 DNS 传出。

到这一步：数据已经泄露，属于重大安全事件。

13. Impact 影响（T1485、T1490）。

战术目标：破坏业务。勒索病毒加密文件、删除数据、DoS。

日志：大量文件重命名（勒索后缀）、大量文件删除事件。

补充：14. Discovery 发现（T1087、T1046）。

Discovery【发现】：黑客拿下一台机器之后，在内网扫描，探查内网有哪些主机、账号、网段，找域控。
行为：内网端口扫描、net view、arp 扫描、查询域用户信息。

日志：单主机对内网大量 IP 探测、执行 net、nslookup 命令。

作用：黑客摸清内网拓扑，为横向移动做准备。

三、ATT&CK 和 Splunk ES 工作关系。

1. Splunk ES 的 Correlation Search（关联检索），每一条检测规则都会填写对应的 ATT&CK Tactic / Technique 编号。
例：检测 PowerShell base64 的规则 → 映射 `Execution T1059.001`。
2. Splunk 告警（Notable Event）生成时，会自动打上 ATT&CK 标签。你做事件研判，第一步看标签判断攻击阶段。
3. 威胁狩猎：你写 SPL 检索，按照 ATT&CK 技术去寻找证据。
狩猎需求：查找内网有没有攻击者使用 PsExec 横向移动（T1021.002），你就写 SPL 检索 Sysmon 里 PsExec 进程和 SMB 远程执行日志。
4. 事件处置报告：安全事件上报，必须写：本次攻击链路：初始访问（钓鱼）→执行→凭证窃取→横向移动，标注每个环节 ATT&CK 编号。

四、高频技术 + 子技术【必须记住，Splunk ES 告警经常出现】。

记住：技术编号 + 名称 + 攻击行为 + 对应日志。低频技术直接网页查。

1. T1059 命令和脚本解释器（Execution 执行）。
   - T1059.001 PowerShell。
   行为：powershell 执行恶意脚本、base64 编码命令。
   日志：Sysmon EventCode1，powershell.exe 命令行。

2. T1003 凭证转储（Credential Access 凭证访问）。
   - T1003.001 LSASS 内存凭证窃取（Mimikatz）。
   行为：读取 lsass 进程抓取内存账号哈希。
   日志：Sysmon，访问 lsass.exe 进程。

3. T1021 远程服务会话（Lateral Movement 横向移动）。
   - T1021.002 SMB/PsExec。
   行为：PsExec 通过 SMB 远程在别的机器创建进程。
   日志：Sysmon 远程进程创建、SMB 连接日志。
   - T1021.001 RDP。
   行为：远程桌面登录横向移动，Windows 登录事件 4624。

4. T1136 创建账号（Persistence 持久化）。
   - T1136.001 创建本地账号（后门账号）。
   日志：Windows 安全事件 4720（创建用户）。

5. T1053 计划任务 / 作业（Persistence 持久化）。
   - T1053.005 Windows 计划任务。
   行为：创建定时任务，开机 / 定时执行后门。
   日志：4698 创建计划任务。

6. T1562 禁用 / 修改安全防御（Defense Evasion 防御规避）。
   - T1562.001 清除 Windows 事件日志。
   日志：EventCode 1102 日志被清除（高危告警！）。

7. T1190 通过公共应用漏洞初始访问（Initial Access）。
行为：利用对外网站 / 服务漏洞打进内网，如 Exchange 漏洞。

8. T1566 钓鱼（Initial Access 初始访问）。
   - T1566.001 钓鱼邮件（带恶意附件 / 链接）。

事件 ID ；含义；关联 ATT&CK 方向：

4624；成功登录；初始访问、横向移动。
4625；登录失败（暴力破解）；初始访问。
4688；进程创建（旧版 Windows，Sysmon1 更推荐）；Execution 执行。
4720；新建用户账号；Persistence 持久化。
4698；创建计划任务；Persistence 持久化。

五、基础概念【全部记住，面试必考，研判必用】。

1. Tactic（战术）：攻击者的目标（大阶段）。
2. Technique（技术）：实现目标的具体方法。
3. Sub-technique 子技术：同一技术下细分实现方式，格式 Txxxx.001。
4. IOC：指标（恶意 IP、域名、文件 hash），静态指标，Splunk lookup 匹配告警。
5. TTP：战术、技术、流程（ATT&CK 描述的就是 TTP，用来描述攻击者行为）。
6. MITRE ATT&CK 是攻击者视角，不是防护清单。
7. ATT&CK 不是固定顺序，攻击者可以跳跃、重复执行各个战术。
8. ATT&CK Enterprise 矩阵：企业内网 SOC 使用；ICS / 移动端不用深入学习。
