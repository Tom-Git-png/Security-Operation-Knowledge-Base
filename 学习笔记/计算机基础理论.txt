前置知识：

-ICMP 互联网控制报文协议，ping、端口不可达报错。
-TCP 传输控制协议，记死 6=TCP。
-UDP 用户数据报协议，记死 17=UDP。

协议扩展：

-协议0 HOPOPT逐跳选项。
-协议2 IGMP组播，内网设备发现。
-协议41 IPv6 ipv6报文。
-协议50 ESP IPsec加密，VPN。
-协议51 AHIPsec 认证，VPN。

-协议号：IP 头部，区分是 TCP 还是 UDP；
-端口：TCP/UDP 头部，区分上层是什么应用服务。

TCP/UDP:

TCP（协议号 6）:
-面向连接，通信前建立连接，通信完释放连接。
-可靠传输：序列号、ACK 确认、超时重传。
-字节流模式，没有报文边界。
-有拥塞控制、流量控制。
-应用：SSH (22)、HTTP (80)、HTTPS (443)、RDP (3389)、SMB (445)、MySQL (3306)。

TCP Flags 标志:

-SYN 同步，发起连接请求 扫描、SYN 洪水大量 SYN 包。
-ACK 确认报文 正常通信绝大部分包带 ACK。
-FIN 结束，正常关闭连接 正常会话结束。
-RST 重置连接，强制断开 端口关闭、防火墙拦截、扫描返回 RST。
-PSH 推送，立即上交数据给应用 木马通信会出现。
-URG 紧急数据 恶意程序利用。
-异常组合：SYN+FIN、SYN+RST，正常业务不会出现，疑似扫描探测。

三次握手：

-客户端 → 服务端：SYN=1 请求建立连接。
-服务端 → 客户端：SYN=1，ACK=1 应答。
-客户端 → 服务端：ACK=1，连接建立完成，传输业务数据。

-只大量收到 SYN，没有 SYN‑ACK、ACK 是 SYN 扫描 或者 SYN 洪水 DDoS。

四次挥手：

-客户端发 FIN，表示不再发送数据。
-服务端回 ACK 确认 FIN。
-服务端发 FIN，表示自己也没有数据发送。
-客户端回 ACK 确认，连接关闭。

-大量 RST 代替 FIN 挥手，代表连接被粗暴切断，防火墙阻断 / 恶意行为。

TCP 两个状态：

-TIME‑WAIT：主动关闭方等待，确保对方收到 ACK；大量 TIME‑WAIT：短时间大量新建关闭连接（扫描、爆破）。
-CLOSE‑WAIT：程序没有调用关闭，代码问题。

TCP 相关威胁：

-SYN 半开扫描 (nmap‑sS)：只发 SYN，不完成三次握手，日志很难记录完整会话。特征：同一源 IP，大量不同目的端口 SYN 包。
-SYN 洪水 DDoS：海量 SYN 报文，不完成握手，耗尽服务器半开连接队列。
-暴力破解：SSH/RDP/Mysql，TCP 协议，大量新建连接，大量失败握手。
-SMB (445) 勒索病毒传播，TCP。
-C2 木马长 TCP 外连。

UDP（协议号 17）：

-无连接，不需要握手，发完就结束。
-不可靠，无 ACK、无重传，丢包不管。
-头部很小只有 8 字节，开销小速度快。
-可以伪造源 IP！这是 UDP 最大安全问题。

常用 UDP 端口：

- 53 DNS（小查询 UDP，大包 DNS/DNSSEC 走 TCP）。
- 123 NTP。
- 161 SNMP。
- 1900 SSDP/UPnP。

UDP 重点威胁：

-UDP 洪水：大量 UDP 小包打目标，占满带宽。
-DRDoS 反射放大攻击。
原理：攻击者伪造受害者 IP，向公网开放 UDP 服务（NTP/DNS/SSDP）发送小请求；服务器向受害者返回放大后的大流量。
-为什么 UDP 可以做 DRDoS？UDP 无连接，不需要握手，支持伪造源 IP；TCP 很难伪造源 IP 做反射攻击。
-UDP 扫描 (nmap‑sU)：发包，收到 ICMP 端口不可达代表端口关闭；无响应代表端口可能开放。扫描速度慢。

-ICMP Type3 Code3：端口不可达，UDP 扫描依靠这个 ICMP 报文判断端口状态。

-TCP 面向连接，UDP 无连接 。
-TCP 可靠，UDP 不可靠 。
-TCP 头部 20‑60 字节，UDP 头部固定 8 字节 。
-DRDoS 主要基于 UDP 。
-SYN 洪水是 TCP 的 DDoS 。
-DNS 53 端口，UDP 用于普通查询，TCP 用于大包 DNS 。
-协议号：TCP=6 UDP=17 ICMP=1 。

Wireshark 过滤语句：

tcp.flags.syn == 1  //过滤SYN包。
tcp.flags.rst == 1  //过滤RST重置包。
udp  //所有udp流量。
tcp.analysis.retransmission  //TCP重传报文。

-三次握手只看到大量 SYN 包，没有后续 ACK 是什么行为？ 
两种可能：SYN 半开端口扫描；SYN 洪水 DDoS 攻击。攻击者只发送 SYN 报文，不完成三次握手。

-DRDoS 反射放大攻击为什么大多使用 UDP，不用 TCP？
UDP 无连接，不需要握手，可以直接伪造源 IP。TCP 需要三次握手，伪造源 IP 无法收到 SYN‑ACK，握手无法完成，很难实现反射放大。

-大量 RST 包出现，有哪些场景？
目标端口没有开放；防火墙 / 安全设备拦截会话；恶意扫描探测；会话异常中断。

-DNS 端口 53，TCP 和 UDP 区别？
普通域名查询使用 UDP；当报文较大、DNSSEC 场景，使用 TCP。

-SYN 扫描和全连接扫描区别？
SYN 扫描 (-sS) 只发送 SYN，不完成完整握手，日志不容易留存完整会话；全连接扫描 (-sT) 完成完整三次握手，会在系统留下会话日志。

-UDP 扫描怎么判断端口是否开放？
发送 UDP 数据包，如果收到 ICMP 端口不可达报文，端口关闭；没有返回报文，端口大概率开放。

OSI七大模型：

-第一层 应用层 。
核心作用：面向用户应用程序服务。
典型设备/协议：HTTP/HTTPS,FTP,DNS,SMB,SSH,SFTP,POP3,DHCP。
网关，代理服务器，WAF，负载均衡。
关注点：web攻击（SQL注入，XSS）,DNS劫持,文件上传，包含漏洞，绝大多数SOC告警。

-应用层面向业务应用，为软件提供网络访问能力，Web 攻击、邮件威胁大多发生在这一层，WAF 主要工作在应用层。

-第二层 表示层。
核心作用：数据格式转换，加密解密，编码压缩。
典型设备/协议：数据加密，解密，字符编码，JPEG、ASCII 编码、SSL/TLS。
关注点：数据编码漏洞，SSL/TLS加密解密，数据格式解析漏洞。
TLS/SSL 加密解密；证书问题；加密流量无法直接解析内容。

-表示层负责数据的格式转换、编解码、加密解密，完成不同系统之间数据语法兼容，TLS 加密属于本层功能。

-第三层 会话层。
核心作用：建立，管理，断开会话连接。
典型设备/协议：RPC，NETBIOS。
关注点：会话劫持，会话断开，远程会话攻击。

-会话层负责建立、维护、终止两端应用程序的会话连接，管理会话生命周期。

-第四层 传输层。
核心作用：段，端口，端到端传输控制。
典型设备/协议：TCP/UDP。
关注点：端口扫描，TCP会话劫持，SYN洪水，UDP洪水；IDS基于端口识别服务。

-SOC 告警里大量：对外异常外联端口、高危端口访问，就是传输层分析。

-传输层实现端到端通信，通过端口区分主机上不同服务；TCP 可靠，UDP 高效。SYN 洪水、端口扫描发生在传输层，防火墙基于端口做访问控制。

-第五层 网络层。
核心作用：数据包，IP寻址，跨网路段路由。
典型设备/协议：路由器，三层交换机，IP,ICMP。
关注点：IP扫描，IP欺骗，路由攻击，防火墙IP策略，ICMP洪水，路由劫持。

-网络层基于 IP 地址完成寻址与路由，实现跨网段转发，我们封禁恶意攻击 IP 就是在网络层做阻断。

-第六层 数据链路层。
核心作用：帧，MAC地址，局域网内通信。
典型设备/协议：交换机，网桥，协议，Ethernet 以太网,ARP。
关注点：ARP欺骗，MAC泛洪，VLAN共计，二层劫持，交换机端口安全。

-数据链路层负责局域网内通信，依靠 MAC 地址，ARP 欺骗、内网嗅探属于该层安全问题，二层交换机工作在此层。

-第七层 物理层。
核心作用：比特流，物理硬件，电压，网线，光纤。
典型设备/协议:网线，光纤，集线器，网卡硬件。
关注点：物理破坏，线路窃听，物理接入，设备断电。

-物理安全：拔网线、设备断电，物理破坏。

-每层数据单位（考试高频考点，SOC 面试常考）。

1. 物理层：比特 (bit)。
2. 数据链路层：帧 (frame)。
3. 网络层：数据包 / 分组 (packet)。
4. 传输层：段 (segment‑TCP) / 数据报 (datagram‑UDP)。
5‑7 层：数据 (data)。

-SOC 安全运营重点记忆（工作实用）。

1. 1‑4 层：底层网络攻击，DDoS、ARP 欺骗、端口扫描，防火墙、IPS 处理。
2. 5‑7 层：应用攻击，Web 漏洞、木马、恶意请求，WAF、EDR、应用告警。
3. 封装顺序：应用层→表示层→会话层→传输层→网络层→数据链路层→物理层（发送数据从上往下封装）。
4. 解封装顺序：物理层→数据链路层→网络层→传输层→会话层→表示层→应用层（接收数据从下往上拆包）。

-MAC 地址：二层；IP 地址：三层；端口号：四层。

-MAC地址：硬件物理地址，只在同一个局域网生效。

-IP地址：跨网段寻址，公网/内网IP。

-端口号：TCP/UDP 端口，区分同一台主机上不同服务。

-ARP 地址解析：IP > Mac。

-ICMP 互联网控制报文 ping,traceroute基于ICMP。

-DNS 域名 > IP。

-VlAN 虚拟局域网，交换机划分广播域。

-SSL/TLS 加密解密，数据格式加密处理：HTTPS = HTTP（7层）+TLS（6层）。

-传统防火墙（硬件防火墙 / 下一代防火墙 NGFW）。

工作层级：网络层 (3)+ 传输层 (4)，NGFW 会部分到应用层，但主力还是 3‑4 层。
看的内容：源 IP、目的 IP、源端口、目的端口、TCP 连接状态。

1. 允许 / 禁止某个 IP 访问。
2. 放行 / 封禁端口，比如禁止外网访问 3389、22 端口。
3. 做 NAT、会话状态检测，拦截 SYN 洪水。
4. 可以阻断来自恶意 IP 的全部数据包。

看不懂 HTTP 报文里面的内容。
就算数据包里面藏了 SQL 注入、XSS，防火墙只看 IP 端口，识别不出来，会直接放行。

SOC 工作场景：遇到暴力破解，直接在防火墙封禁攻击源 IP。

-WAF Web 应用防火墙。

工作层级：应用层 7 层。
看的内容：完整的 HTTP/HTTPS 请求：URL、请求参数、body、cookie、header。

1. 识别 Web 攻击：SQL 注入、XSS 跨站脚本、CSRF、命令注入、文件上传攻击。
2. 拦截恶意请求 payload，防护网站、Web 接口。
3. 防护爬虫、CC 攻击（Web 层）。
4.不管普通端口，比如 SSH22、RDP3389 这种非 Web 协议，WAF 管不到。
5.WAF 只处理 Web 流量（80/443）。

SOC 工作场景：SIEM 收到 WAF 告警，提示 SQL 注入攻击，就是 WAF 解析 HTTP 内容抓到的威胁。
