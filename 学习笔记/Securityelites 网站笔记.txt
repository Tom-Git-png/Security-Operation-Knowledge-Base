扫描漏洞教程：

-dig target.com ANY 域名查询。

-curl https://crt.sh/?q=%.target.com&output=json。
作用：**从 HTTPS 证书日志挖掘子域名**，很多隐藏子域名会出现在证书中，是子域名收集非常经典手法。

-dig @ns1.target.com target.com AXFR。
作用：**尝试 DNS 域传送漏洞**。
如果 DNS 服务器配置错误，允许外部 AXFR，会直接把这个域名全部 DNS 记录完整导出所有子域名、解析记录全部拿到，属于高危配置错误）。

-200 OK——一个本应返回 403 状态码的页面却返回了 200 状态码？这确实是个值得注意的情况。

-201 对象被创建了——确认了这些对象的创建情况——但这里存在对象数据分配错误的风险。

-204 无内容 — 通常是 DELETE 响应的结果。

-301 移动——检查位置头信息——在此处进行重定向测试。

-找到 302 响应——大多数重定向测试都发生在这一阶段。

-401 未授权 — 找到那些返回 200 响应的终端节点，它们实际上应该返回 401 状态码。

-403 禁止访问 — 属于 IDOR 测试环境 — 尝试使用其他用户的 ID 来获取 200 的响应。

-429 速率限制——通过不同的 IP 地址、用户代理头信息以及 X-Forwarded-For 字段进行测试绕过。

-500 内部错误——您的输入引发了意外行为。可能存在注入攻击的风险。请仔细检查并采取措施应对。

-502 错误，属于 Bad Gateway 问题——这类错误可能会暴露系统的内部架构和后端服务。

-Content-Security-Policy 缺少此功能意味着没有 XSS 防护。没有这种防护意味着 XSS 恶意代码更有可能生效。

-X-Frame-Options 如果缺失了什么，那么点击劫持行为就有可能发生。这属于中等程度的隐患。

-Strict-Transport-Security 缺失项意味着可能存在 SSL 剥离现象。在大多数程序中都出现了较低的结果。

-Server: Apache/2.2.31 版本信息披露：Apache 2.2.31 已经不再受支持，其安全漏洞需要立即进行上报。

-X-Powered-By: PHP/7.1.0 EOL PHP 系统存在已知的 RCE 漏洞。务必针对具体版本进行相关研究。

-X-Debug-Token: 1a2b3c 调试模式保持开启状态。通常能够显示堆栈跟踪信息以及内部路径信息。这是一个非常重要的发现。

-OWASP 10大漏洞原理：
A01 漏洞控制机制存在漏洞。
A02 密码学故障-加密被破解，缺失或滥用的情况。
A03 注入-当用户输入的数据不进入代码或命令时。
A04 设计存在缺陷-当应用程序的逻辑成为漏洞所在时。
A05 安全配置缺陷-默认设置存在问题，防护措施缺失。
A06 存在漏洞且过时的组件-已知存在CVE问题，在生产环境中持续运行。
A07 身份识别与认证失败-账户劫取的途径。
A08 软件和数据完整性故障-无需验证即可信任。
A09 安全日志记录与故障监控-默默无闻的保障者。
A10 服务器端请求伪造(SSRF)-让服务器自己成为黑客的靶子。
