-goroutine（协程）。
1. 轻量级，但不是无限。
- 初始栈只有 2KB，可动态扩缩栈，可以轻松开几万、几十万；
- 受内存限制，不是没有上限，疯狂创建会内存耗尽 OOM。“协程数量没有限制” 是错误选项。
2. 对比 OS 线程。
- OS 线程：内核管理，栈几 MB，开销大，数量不能太多
- goroutine：Go runtime 管理，协程比线程轻量。“线程比协程更轻量” 错。
3. 协程也会死锁。
- 无缓冲 channel 写了没人读 / 读了没人写；
- 多个 goroutine 互相等待对方；
- main 协程等待子协程逻辑写错；
- Go 运行时部分场景能检测死锁，直接 panic。“协程不存在死锁” 错误。
4. go func (){}() 启动 goroutine；main 退出，所有 goroutine 直接结束。

-channel（通道）。
1. 核心理念：不要共享内存通信，通过通信共享内存，goroutine 之间优先用 channel 通信。
2. 两种类型。
- 无缓冲 channel：读写必须配对，一方阻塞等另一方。
ch := make(chan int)。
-有缓冲 channel：缓冲区未满写不阻塞；缓冲区不为空读不阻塞。
ch := make(chan int, 10)
3. channel 关闭规则。
- 只能发送方关闭 channel；接收方关闭会 panic。
- 关闭后的 channel 还可以读，读到零值；往已经关闭的 channel 发送数据，直接 panic。
- 重复关闭 channel，panic。
4. for‑range 读 channel：channel 关闭后，range 循环自动退出。
5. select。
- select 监听多个 channel；有多个就绪随机选一个；没有 case 就绪就阻塞；有 default 就不阻塞直接走 default。

-interface{}：万能盒子，随便丢东西，Go 自动帮你打包。工作里 99% 用这个。

-*interface{}：盒子的指针，很少用！不会自动造盒子。你不能扔石头、不能扔石头的地址；只能扔已经造好的盒子的地址。
